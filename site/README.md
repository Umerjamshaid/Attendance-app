# P Attendance Website

Static Next.js showcase for the Flutter app. It has no account system, API
routes, Supabase configuration, analytics, or access to employee data.

## Preview

From `site/` (Node.js 24 LTS recommended):

```sh
npm ci
npm run dev
npm run build
```

The build produces `site/out/`. For a custom domain or a root deployment,
leave `NEXT_PUBLIC_BASE_PATH` unset. A repository Pages URL such as
`/Attendance-app/` needs `NEXT_PUBLIC_BASE_PATH=/Attendance-app` at build time.

## Publish

1. Merge the site into the repository's default branch when it is approved.
2. Open **Settings > Pages** and choose **GitHub Actions** as the source.
3. In **Actions**, manually run **Publish Attendance site** on the default branch.

If **Configure Pages** fails with `Get Pages site failed` and a 404, check
**Settings > Pages** and select **GitHub Actions** as the publishing source
before rerunning. The workflow cannot create the Pages site; this step
fails before the Next.js build begins.

The workflow configures the Pages base path and uploads only `site/out/`.
For another static host, set `site/` as the project directory,
`npm run build` as the build command, and `out/` as the publish directory.

By default the download action opens GitHub Releases. To link a newer APK
directly, attach an approved public build to a GitHub Release and set
`ATTENDANCE_APK_URL` as a repository Actions variable. It must be a public
HTTPS URL ending in `.apk`, with no query or credentials. Do not add local APKs
or private builds to the site.

## Assets and Motion

- The phone screens are real Flutter renders with fictional records generated by
  `flutter test --no-pub --update-goldens tool/capture_site_screens_test.dart`
  from `attendance/`. Do not replace them with captures of a live office.
- The logo and DM Sans font come from Attendance. The font's OFL is in
  `public/fonts/OFL-DMSans.txt`. CSS supplies the simple device frames.
- BunPod inspired the product-first presentation; no BunPod assets or copy
  were used. GSAP sequences the introduction, scroll-driven phone movement,
  and check-in receipt morph. Lenis is the only smooth-scroll engine. Reduced
  motion shows the finished states immediately. No 3D canvas.
- The sample check-in only replays the receipt in the browser. It captures
  nothing and sends no requests to the app backend.

## Backend Boundary

GitHub Pages only hosts the public site. App auth, office memberships, and
check-in evidence stay in Supabase. Any future employee web portal should be a
separate authenticated surface, after verifying invitation/recovery,
cross-office authorization, and check-in retry behavior in staging.
